# Decisions

The architecture and product choices that hold today, with the reason for each. A superseded
decision stays in the table, marked, so the history makes sense.

| # | Decision | Reason |
|---|---|---|
| D1 | Stack Tauri 2 + Rust + React/TypeScript | Rich charts (ECharts) weighed more than a static binary; one codebase for macOS, Linux and Windows. |
| D2 | SQLite + SQLCipher with a master password (Argon2id); the password and the file itself always open the database. Quick unlock (biometrics, hardware key) is optional and stores the key protected by the system; the demo vault has no password (D26) | Local-first, a single file, transparent encryption, no key file to lose. |
| D3 | Base currency per vault (that of the country chosen at creation), multi-currency in accounts and assets | A family with accounts and assets in other currencies; conversion through the country's official exchange rate source (PTAX in Brazil). |
| D4 | Weighted average price as the default cost method in Brazil | Brazilian Federal Revenue rule; other countries use their own rule ([cost-method.md](cost-method.md)). |
| D5 | The country's official inflation as the default deflator (IPCA in Brazil); CPI and M2 optional | The real result is the app's central question; M2 gives an alternative view of currency "dilution". |
| D6 | One vault per family, no login per member | Simplicity. Members are holders of accounts and transactions; "View as" and the per-member profile (D25) cover each person's view. |
| D7 | The agent acts as a financial manager through the app's own MCP: it reads, recommends and writes, with approval, undo and audit | A single tool surface for the internal agent, CLIs and external clients. |
| D8 | Measuring-instrument look, dark theme by default | Numbers with their origin in view, density with room to breathe ([design.md](design.md)). |
| D9 | MCP as the `treasury mcp` subcommand of the same binary | A single executable per platform. |
| D10 | Expense visualizations as a central piece | Sankey, treemap, heatmap, comparisons, nominal × real. |
| D11 | AI engines configurable per task: APIs, local CLIs using the user's subscription and local models through an endpoint | Reduce cost by using subscriptions the family already has ([ai-agent.md](ai-agent.md)). |
| D12 | Single-file database (`~/.treasury/data/treasury.db`), journal without WAL, attachments inside the database | Simplicity, portability, trivial backup. |
| D13 | Backups managed by the app in `~/.treasury/backups/` (configurable), encrypted, verified and rotated | Protection against data loss without depending on the user ([backup-recovery.md](backup-recovery.md)). |
| D14 | Complete portfolio and asset analysis inside the app: portfolio, indicators, rankings, screener, dividends and income tax | The family does not need a paid platform to follow its investments ([investments.md](investments.md)). |
| D15 | Isolated assisted browser to bring in data from banks; **superseded by D20** | — |
| D16 | Money amounts as integers in the smallest unit; quantities and unit prices in exact decimal | Precision without floating point, including for fractions and crypto. |
| D17 | Every write goes through `change_set` (user, import and AI) | A single mechanism for undo, history, approval and audit. |
| D18 | Each module is born with its own read-only MCP tools | What the interface shows, an MCP client can also read. |
| D19 | Source catalog per country | Outside Brazil, inflation, interest rates and exchange rates come from free official sources (ECB, Eurostat, OECD, Bank of Canada, ONS, BoE, World Bank) ([data-sources.md](data-sources.md)). |
| D20 | No embedded browser; data comes in through import | Internet banking sites detect that the embedded browser is not an ordinary browser. Import (OFX/CSV, card statements and notes in PDF, B3 reports, the Downloads folder, e-mail, attachments to the agent) covers the same data. V108 deleted the browser's tables and settings; external links open in the system browser. Exception: the NFC-e lookup at the SEFAZ that ask for a captcha opens in an app window locked to `https` on `.gov.br` (and to the captcha frames), with no permission at all and with the session erased on close; the person solves the captcha there and nothing bypasses it ([ocr-receipts.md](ocr-receipts.md) §4). |
| D21 | Local AI with a model download inside the app; **superseded by D23** | — |
| D22 | Experience levels (Beginner, Intermediate, Advanced), with a welcome questionnaire that can be skipped | Useful for those with little familiarity with finance without hiding the advanced features ([profile.md](profile.md)). |
| D23 | No embedded AI engine: local models come in like any engine, through an endpoint (Ollama, LM Studio or OpenAI-compatible). The embedded OCR (small models inside the binary, only to read text from a photo, no download) is not an AI engine | In a test with 85 statement descriptions, a small general-purpose model got 79% of the categories right against 14% for the embedded model evaluated before; keeping an engine of our own was not worth it. V110 deleted the `local_ai.*` settings. |
| D24 | Several vaults: each `.db` with its own password, quick unlock and backups, listed in `config.toml` | Separate purposes (a small business's cash flow, without accounting; the parents; testing) without mixing data ([vaults.md](vaults.md)). |
| D25 | Finances per member with "View as" and a knowledge profile per member | What comes in, goes out and is left over for each person, in each one's language ([members.md](members.md)). |
| D26 | Demo vault generated by a wizard, always in a new and separate vault, with fictional quotes | Try the app with a family similar to yours without mixing real data ([demo.md](demo.md)). |
| D27 | The app asks for the family's country and adapts to it: Brazil complete, some countries adapted, the others in generic mode | Brazil's sources, fields and analyses make no sense for a family abroad ([countries.md](countries.md)). |
| D28 | Brazilian income tax (IR) calculation on the current basis: monthly variable income, DARF, assets and rights and the tax return report | Covers what the family needs to file; new rules come in when there is demand ([taxes.md](taxes.md), [income-tax-validation.md](brazil/income-tax-validation.md)). |
| D29 | Open source on GitHub (`knuppe/treasury`), AGPL-3.0-only license, contributions with DCO and no CLA | Predictable license; DCO is light for contributors ([CONTRIBUTING.md](../CONTRIBUTING.md)). |
| D30 | App identifier `io.github.knuppe.treasury` (also the Keychain service) | A domain of the project itself; changing it later would force migrating every installation. |
| D31 | The documentation and the interface do not name competing products or analysis sites | Only the data sources and APIs the app actually uses appear by name. |
| D32 | Only the maintainer publishes releases: CI builds with attestation, his YubiKey signs on the Mac, publishing is manual, and the app refuses an update without the YubiKey signature | People put their financial life in the app; trust is in an identified person, not in an account or a server ([trust.md](trust.md)). |
| D33 | All packages update themselves (macOS, AppImage, `.deb`, `.rpm`, NSIS, `.msi`) | Nobody stays on an old version because of the package type ([auto-update.md](auto-update.md)). |
| D34 | Donations with no counterpart: they unlock no feature, priority or support, and the reminder does not appear on the market, score and portfolio screens | A donation with a counterpart becomes a sale (consumer law) and, near the score, would look like payment for analysis ([support.md](support.md), Terms 7). |
| D35 | Themes, easter eggs and texts do not use names, phrases, characters or brands of films, series or companies | A work's name as a feature name suggests a license or endorsement; the theme describes what is seen ([design.md](design.md)). |
| D36 | The project does not give opinions on assets: README, site, issues and examples do not say whether an asset is good, cheap or expensive, and screenshots use the demo vault | The app calculates with the data and criteria of whoever uses it; a published opinion on an asset is securities analysis (Terms 5.2). |
| D37 | Third-party components ship with their licenses: `THIRD_PARTY_LICENSES.md` generated in the repository and in the installers, licenses accepted in `deny.toml` | MIT, BSD, Apache and OFL require the notices alongside the binary; a dependency with an incompatible license blocks CI. |
| D38 | The name stays "Treasury", with no trademark registration | There are trademarks with the word in the US (investment services) and an application in Brazil (financial services); the app is local, free software, the word is descriptive and coexists with dozens of composite marks. The risk is having to change the name if there is a complaint. Precautions: no logo, color or text that resembles another brand; the README says it is a personal project with no tie to a company or government; a notification received is not ignored. |
| D39 | Basket health (ultra-processed, "high in", protein per real) stays in Consumption, and each member's allergies and restrictions stay only in the vault: they do not go to the MCP or to the agent's screen context (the test `every_read_shown_by_the_interface_has_a_tool` keeps `food.diet_list` and `food.health_summary` out of the catalog) | It helps see where the grocery money goes, but allergy and restriction are health data (a sensitive category under the LGPD and the GDPR); outside the MCP, no AI engine receives them ([gtin-inflation.md](gtin-inflation.md) §7.2). |
| D40 | Asset news: only headline, outlet, date and link, never the text or a summary of our own; search by ticker only with the source turned on by the person | Show what came out about an asset without becoming editorial content (out of scope in [vision.md](vision.md)) or the project's opinion (D36). |
| D41 | The free calculators do their math in the interface, in floating point, with no core command or MCP tool | They are simulations with typed numbers, with no vault data and saving nothing; decimal precision (D16) and the MCP tools (D18) apply to what uses or saves the family's data ([calculators.md](calculators.md)). |
